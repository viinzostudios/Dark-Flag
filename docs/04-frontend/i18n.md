# Internacionalización (i18n)

## Resumen

El sistema de i18n usa [`@ngx-translate/core@17`](https://github.com/ngx-translate/core) con 10 idiomas. El idioma se detecta automáticamente al cargar la app (browser locale + localStorage) y se sincroniza con el perfil del usuario autenticado.

## Archivos de traducción

Ubicación: `frontend/public/i18n/{lang}.json`

Cada archivo tiene las mismas secciones en el mismo orden:

```
lobby.*          — Lobby principal
pre_entry.*      — Overlay de pre-entrada a partida
daily_reward.*   — Recompensa diaria
register_prompt.*— Prompt para registrarse (guest)
rankings.*       — Modal de rankings
avatar_picker.*  — Selector de avatares
auth.*           — Login, registro, recuperación de contraseña
stats.*          — Pantalla de estadísticas
shop.*           — Tienda (skins, arenas, avatares, paquetes)
nav.*            — Navegación global
errors.*         — Mensajes de error genéricos
lang_selector.*  — Selector de idioma
hud.*            — HUD in-game (Phaser)
skins.*          — Nombres de skins de tanques (slug → nombre traducido)
arenas.*         — Nombres de arenas/escenarios (slug → nombre traducido)
avatars.*        — Nombres de avatares/stickers (slug → nombre traducido)
```

---

## Regla obligatoria

**Toda nueva pantalla, componente o string visible para el usuario debe agregarse a los 10 archivos JSON antes de ser usada en el código.**

Pasos:
1. Definir las claves bajo la sección apropiada (o crear una nueva)
2. Agregar traducción en los 10 archivos
3. Usar `| translate` en templates o `TranslateService.instant()` en TypeScript

---

## Uso en componentes Angular

### Template
```html
<!-- Texto simple -->
{{ 'section.key' | translate }}

<!-- Con parámetros de interpolación -->
{{ 'lobby.claimable_label' | translate : { count: n } }}

<!-- Atributos -->
[placeholder]="'lobby.alias_placeholder' | translate"

<!-- Key dinámica -->
{{ ('avatar_picker.cat_' + cat) | translate }}
```

### TypeScript
```typescript
// Importar en el componente
import { TranslateModule, TranslateService } from '@ngx-translate/core';

// En el decorator
imports: [TranslateModule, ...],

// En la clase
private readonly translate = inject(TranslateService);

// Uso
const msg = this.translate.instant('shop.equip_error');
const msgParam = this.translate.instant('lobby.claimable_label', { count: 3 });
```

## Uso en HUD (Phaser)

HUD.ts no puede usar Angular DI directamente. Recibe una función de traducción via `TranslateFn`:

```typescript
// game.config.ts
export type TranslateFn = (key: string, params?: Record<string, unknown>) => string;

// game.component.ts — se registra en Phaser registry
(key, params) => this.translate.instant(key, params)

// HUD.ts — se recibe como constructor arg
constructor(scene, isMobile, private readonly t: TranslateFn = (k) => k)
```

El flujo: `GameComponent` → `buildPhaserConfig(translateFn)` → `game.registry.set('translateFn', fn)` → `GameScene.create()` lee la fn → pasa a `new HUD(scene, isMobile, fn)`.

## Nombres de ítems dinámicos (skins, arenas)

Los skins y arenas tienen nombres que se almacenan en la base de datos. Para traducirlos sin modificar el backend, se usa un sistema de **claves basadas en slug**:

### Convención de slugs

El slug se genera automáticamente desde el nombre original:

```typescript
function skinSlug(name: string): string {
  const diacriticRe = new RegExp('[\\u0300-\\u036f]', 'g');
  return name.normalize('NFD').replace(diacriticRe, '').toLowerCase()
    .replace(/\s+/g, '-').replace(/[^a-z0-9-]/g, '');
}
// 'El Dragón Carmesí' → 'el-dragon-carmesi'
// 'Lava Subterránea'  → 'lava-subterranea'
```

Las arenas ya tienen un `slug` nativo en la entidad `ArenaSkin` (campo `slug`) que se usa directamente como clave.

### Sección `skins.*` en los JSON

Contiene 100 entradas (una por skin) con formato `slug → nombre`:

```json
"skins": {
  "base-clasico": "Classic Base",
  "el-verde": "The Green",
  "el-dragon-carmesi": "The Crimson Dragon",
  ...
}
```

### Sección `arenas.*` en los JSON

Contiene 20 entradas (una por arena premium) con el slug del campo `ArenaSkin.slug`:

```json
"arenas": {
  "lava-subterranea": "Underground Lava",
  "profundidades": "The Depths",
  ...
}
```

### Sección `avatars.*` en los JSON

Contiene 210 entradas (una por avatar) con el slug del campo `Avatar.slug`:

```json
"avatars": {
  "avatar-01": "Roaring Lion",
  "avatar-02": "Wise Owl",
  "avatar-210": "Crescent Moon",
  ...
}
```

El slug `avatar-XX` se usa directamente como clave (no requiere cálculo).

### Helpers en los componentes (con fallback)

`LobbyComponent`, `ShopComponent` y `AvatarPickerComponent` exponen los helpers correspondientes:

```typescript
skinName(name: string): string {
  const key = 'skins.' + skinSlug(name);
  const t = this.translate.instant(key);
  return t === key ? name : t;  // fallback: nombre original
}

arenaName(slug: string, fallbackName: string): string {
  if (slug === 'default') return this.translate.instant('shop.default_arena_name');
  const key = 'arenas.' + slug;
  const t = this.translate.instant(key);
  return t === key ? fallbackName : t;  // fallback: nombre de BD
}

avatarName(slug: string, fallback: string): string {
  const key = 'avatars.' + slug;
  const t = this.translate.instant(key);
  return t === key ? fallback : t;  // fallback: nombre de BD
}
```

### Uso en templates

```html
<!-- En lobby: skin name -->
<span class="claimable-name">{{ skinName(s.name) }}</span>

<!-- En lobby: arena activa -->
<span class="skin-name">{{ activeArenaName() }}</span>

<!-- En shop: arena en la lista -->
<div class="arena-shop-name">{{ arenaName(s.slug, s.name) }}</div>

<!-- En shop / avatar-picker: nombre de avatar -->
<span class="av-name">{{ avatarName(a.slug, a.name) }}</span>
```

### Extensibilidad

Para agregar un nuevo skin, arena o avatar en el futuro:
1. Calcular el slug: `skinSlug(nombre)` (skins), slug nativo (arenas), `avatar-XX` (avatares)
2. Agregar la clave `skins.{slug}`, `arenas.{slug}` o `avatars.{slug}` en los 10 archivos JSON
3. No se requiere ningún cambio de código — el helper con fallback garantiza que el nombre de BD siga mostrándose si la clave aún no existe en el JSON

## Selector de idioma

Componente: `LangSelectorComponent` — standalone, disponible en lobby (desktop header) y menú mobile.

Inputs:
- `variant: 'nav' | 'header'` — estilo del botón
- `mode: 'dropdown' | 'modal'` (defecto: `'dropdown'`) — en `modal` abre un overlay centrado en lugar del menú desplegable

El modo `modal` se usa en el menú hamburguesa mobile para evitar que el dropdown se salga de la pantalla.

Persiste en `localStorage.ast_lang` y en el perfil del usuario si está autenticado.

## Detección y persistencia del idioma

### Detección automática (primera visita)
`language-detector.ts` sigue esta prioridad:
1. `localStorage.ast_lang` (preferencia previa)
2. IP geolocation → `country-language.map.ts` (mapeo país → idioma)
3. `navigator.language` (idioma del browser)
4. Fallback: `en`

### Persistencia en perfil (usuarios autenticados)
- Al hacer login: `AuthService` llama `GET /users/me` → `LanguageService.syncFromProfile(preferredLang)`
- Al cambiar idioma manualmente: `LanguageService.setLang(code, isLoggedIn)` llama `PATCH /users/me/language`

### Endpoint backend
```
GET  /users/me               → { preferredLang: string }  (JWT requerido)
PATCH /users/me/language     → { lang: string }  (uno de los 10 códigos soportados)
```
